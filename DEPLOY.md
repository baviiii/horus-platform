# Horus — Deploy & End-to-End Test Runbook

Goal: get all three pieces live and prove the loop works.

- **Horus** (this repo) — the multi-tenant hub. Deploys to Vercel.
- **interview-coach-mcp** — an MCP tool server (separate repo). Deploys to Vercel.
- **CareerCraft** — the first product; it is **tenant #1 inside Horus** (seeded as slug
  `careercraft`), not a separate integration.

The relationship in code:

```
CareerCraft (tenant)  ──►  Horus  ──►  interview-coach-mcp
  (a row in Tenant)      (MCP client)     (streamable-HTTP MCP server)
                         connections registry + agent chat
```

You only ever _register_ the coach server as a **Connection** inside the CareerCraft
tenant; Horus connects to it as an MCP client and exposes its tools to the agent.

## Part A — Deploy Horus to Vercel

### A1. Vercel project

Two supported setups. Pick one.

**Setup 1 — repo root (uses `vercel.json` in this repo, recommended):**

- Root Directory: **repo root** (`.`)
- Vercel reads `vercel.json`:
  - install: `pnpm install --frozen-lockfile`
  - build: `pnpm turbo run build --filter=@horus/web`
  - output: `apps/web/.next`

**Setup 2 — app as root directory:**

- Root Directory: **`apps/web`**
- Vercel auto-detects Next.js and runs `next build`.
- Prisma client is generated by the `postinstall` script in `packages/db` (added for exactly
  this reason). No extra config needed.

> Prisma note: `turbo run build` now depends on `@horus/db#db:generate`, and `packages/db`
> also has a `postinstall: prisma generate`. Either setup generates the client. This was the
> one real build blocker — do not remove those.

### A2. Environment variables (Vercel → Settings → Environment Variables)

**Required — the app will not boot without these** (see `apps/web/src/env.ts`):

| Var                             | Notes                                                                                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------ |
| `DATABASE_URL`                  | Supabase **pooled** connection (PgBouncer, port 6543)                                            |
| `DIRECT_URL`                    | Supabase **direct** connection (port 5432) — for migrations                                      |
| `NEXT_PUBLIC_SUPABASE_URL`      | `https://<ref>.supabase.co`                                                                      |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon key                                                                                |
| `NEXT_PUBLIC_APP_URL`           | Your deployed URL, e.g. `https://horus.vercel.app`                                               |
| `SUPABASE_SERVICE_ROLE_KEY`     | Server-only; used by service-role paths                                                          |
| `HORUS_ADMIN_EMAILS`            | Comma-separated. **Put your email here** — grants `/admin` + auto-claims seeded tenants (see A4) |

**Required for the full agent-chat + MCP-tool loop** (step T4). Connection _testing_ (T3)
does **not** need these:

| Var                                                                               | Unlocks                                                                       |
| --------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| `AZURE_AI_PROJECT_ENDPOINT`                                                       | Foundry Agent Service — **hard-required for chat** (client throws without it) |
| `AZURE_SEARCH_ENDPOINT` / `AZURE_SEARCH_API_KEY` / `AZURE_SEARCH_INDEX_NAME`      | knowledge search tool                                                         |
| `AZURE_OPENAI_ENDPOINT` / `AZURE_OPENAI_API_KEY` / `AZURE_OPENAI_EMBEDDING_MODEL` | embeddings / ingest                                                           |

**Optional (degrade gracefully):** `AZURE_CONTENT_SAFETY_ENDPOINT` (no moderation if unset),
`UPSTASH_*`, `STRIPE_*`, `RESEND_API_KEY`, `SENTRY_DSN`. See `.env.example` for the full list.

> The coach connection's bearer token (if any) also goes here — see Part D.

### A3. Database migrate + seed

Run **once**, locally, against the Supabase DB (needs `DIRECT_URL`):

```bash
pnpm db:migrate:deploy   # applies migrations incl. 20260502000000_init_rls
pnpm db:seed             # creates the `platform` + `careercraft` tenants
```

### A4. Supabase Auth setup (needed for the new login/signup)

Supabase Dashboard → **Authentication**:

1. **Providers** → enable **Google** and **Azure** (Microsoft). Paste each provider's
   client ID/secret. Their callback URL is `https://<ref>.supabase.co/auth/v1/callback`.
   - Google: Google Cloud → OAuth consent + credentials.
   - Microsoft: Entra ID → App registration → add the Supabase callback as a redirect URI.
2. **URL Configuration → Redirect URLs** → add `https://<your-app>/api/auth/callback`.
3. **Email templates** → make sure Confirm signup, Magic Link, and Reset Password are enabled.

> Email + password and magic link work with zero provider config. Google/Microsoft buttons
> show _"that sign-in method is not enabled yet"_ until step 1 is done.

## Part B — Deploy interview-coach-mcp

1. Deploy the coach repo to Vercel. Note its **streamable-HTTP MCP endpoint**, e.g.
   `https://interview-coach-mcp.vercel.app/mcp`.
2. The Horus MCP client connects **fresh per request** and is stateless — good for serverless.
3. ⚠️ **Function timeout.** Horus allows up to 60s per tool call (`CALL_TIMEOUT_MS` in
   `packages/core/src/mcp/client.ts`). Vercel Hobby caps functions at ~10s. If a coach tool
   does research + LLM work, it can exceed that → use a paid plan or raise the coach's
   `maxDuration`, and keep tools fast.
4. If the coach requires auth, configure a **bearer token** on it and keep the token value for
   Part D.

## Part C — CareerCraft & becoming its owner

CareerCraft the product deploys on its own (existing app). To operate it _as a tenant owner
inside Horus_:

1. Make sure your email is in `HORUS_ADMIN_EMAILS` (A2).
2. Sign up / log in on Horus with that email.
3. Because you're an admin, `/onboarding` sends you to **`/admin/tenants`** (it no longer mints
   a stray personal workspace — fixed in `apps/web/src/app/onboarding/page.tsx`).
4. Click **CareerCraft**. Visiting `/t/careercraft` auto-creates your `TenantMember` row with
   role **OWNER** (`requireTenantMember` in `apps/web/src/lib/tenant-context.ts`). You now own it.

## Part D — Wire the coach into CareerCraft

In Horus, as CareerCraft's owner: **`/t/careercraft/connections`** → **Add connection**:

- **Name:** Interview Coach
- **Slug:** `interview_coach` (must match `^[a-z][a-z0-9_]{1,31}$` — it namespaces the tools)
- **Endpoint:** the coach `/mcp` URL from Part B
- **Secret ref (only if the coach needs a bearer token):** the **name** of a Vercel env var
  (e.g. `COACH_MCP_TOKEN`). Add that env var in Horus with the token value. Horus reads
  `process.env[secretRef]` and sends `Authorization: Bearer <value>` — the token itself is
  never stored in the DB.

On add, Horus probes the server and stores the discovered tool list. Status should flip to
**CONNECTED** with a tool count.

## The end-to-end test

| #      | Step                                                                                                                      | Validates                        | Needs Azure?               |
| ------ | ------------------------------------------------------------------------------------------------------------------------- | -------------------------------- | -------------------------- |
| **T1** | Sign up, then log in on Horus (try password, magic link, and — once enabled — Google/Microsoft; also run Forgot password) | The new auth surface             | No                         |
| **T2** | Land on `/admin/tenants` → open **CareerCraft**                                                                           | Admin claim → OWNER of tenant #1 | No                         |
| **T3** | `/t/careercraft/connections` → add the coach → **CONNECTED** + tools listed; hit **Test**                                 | Horus ↔ coach MCP wiring         | **No** — cheap smoke test  |
| **T4** | `/t/careercraft/chat` → ask something that should use a coach tool → watch the tool fire and answer                       | The full agent + MCP loop        | **Yes** — Foundry + Search |

**T3 is your Azure-free proof** that the MCP integration works. **T4 is the real thing** and
needs `AZURE_AI_PROJECT_ENDPOINT` (+ Search) live.

## Troubleshooting

| Symptom                                              | Likely cause                                                                                  |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Vercel build fails on `@prisma/client`               | Prisma not generated — confirm `packages/db` `postinstall`/`db:generate` are intact (Part A1) |
| App 500s on boot                                     | A **Required** env var missing (A2) — check Vercel function logs for the `env.ts` error       |
| Google/Microsoft button says "not enabled"           | Provider not enabled in Supabase (A4.1)                                                       |
| Magic/reset link errors on click                     | `/api/auth/callback` not in Supabase Redirect URLs (A4.2)                                     |
| Connection status `ERROR` on add/test                | Wrong `/mcp` URL, coach not deployed, or bad/missing bearer token (Part D)                    |
| Connection `CONNECTED` but chat never calls the tool | Foundry not configured — T4 needs `AZURE_AI_PROJECT_ENDPOINT`                                 |
| Tool call times out                                  | Coach exceeds Vercel function limit (Part B.3)                                                |
| Admin got a stray personal tenant                    | Email wasn't in `HORUS_ADMIN_EMAILS` at first login (Part C.1)                                |
