The one rule: it never sums. Every amount returned is one extracted value, with its source document and quote attached. No endpoint totals amount_aud, because that column mixes discrete measures, portfolio roll-ups ($27.3bn) and balance-sheet stocks ($127bn), across two budget years and two jurisdictions, with duplicates. Adding them up gives a number that appears in no document. The only aggregation is counting. Don't add a totals endpoint.

What counts as a measure

Ranking only means something among like things. All three procedures apply the same filter:

  • Types: program, funding and policy only. metric, where balance-sheet stocks live, is never selectable.
  • The amount must be a JSON number. A malformed row is skipped instead of failing the query.
  • The name must not mark a total (measureNameFilter). It excludes:
    • names starting with Total
    • names containing the whole words revenue(s), receipts, appropriation(s), borrowing(s), liability/ies, assets
    • investing / capital program, expenditure, investment
    • operating balance, net worth, net debt, net lending, cash surplus/deficit
    • short names (≤ 6 words) ending in expenses, payments, expenditure

The rule was calibrated against the live graph: 183 candidates among 2,084 figures. Matching is on whole words, so "RevenueSA Information Online system" stays in. It's still a name rule, so it's approximate; see Known limits.

Tenant scoping

Raw SQL bypasses the tenant extension. All three procedures use ctx.db.$queryRaw, and createTenantScopedClient only rewrites where on model operations. Scoping comes entirely from the "tenantId" predicates in the SQL. Removing one leaks data across tenants.
ProcedureTables, each filtered on its own "tenantId"
periodsentities direct
allocationsentities, relationships, document_entities, documents, and the funder entities all direct
fundersrelationships and both joined entities (funder and measure) all direct

Joined tables are filtered too, not just reached through a filtered row. The schema's foreign keys are single-column, so nothing stops a join row from pointing at another tenant's row. The verify script confirms the other tenants read zero rows.

budget.periods querygraph:read

Input · optional

FieldTypeDefault
minMeasuresint 1–1005

What it does

For each period, it counts distinct name + amount pairs among measures that have a period, and drops periods below minMeasures.

Order

  1. Single financial years (2026-27, consecutive years, not ranges like 2026-30), best-covered first
  2. Then ranges and prose periods, also best-covered first

So a client that defaults to the first entry lands on the main budget year.

Returns

{
  periods: Array<{
    period: string;    // as written: "2026-27", "2026-27 to 2029-30"
    measures: number;  // distinct name + amount pairs
  }>
}

Gotchas

  • measures is an upper bound on the bars allocations will show. A measure extracted under two different names counts twice here, while allocations merges it.
  • A missing year means it has fewer than minMeasures figures. It doesn't mean the year has no data.

budget.allocations querygraph:read

This is the only procedure that returns amounts, and it returns them one measure at a time.

Input · object required

FieldTypeDefaultBehaviour
periodstring ≤ 40all periodsExact match on attributes.period
source'federal' | 'state' | 'other'allFiltered in SQL before LIMIT
types('program' | 'funding' | 'policy')[], 1–3all threemetric can't be selected
limitint 1–10025Applied after merging

Pipeline

  1. Select the tenant's measures of types, matching period if one is given.
  2. Label the source from linked documents: budget-federal → federal, otherwise budget → state, otherwise other. Federal wins when both apply.
  3. Filter by source, sort by amount DESC then id (a stable tie-break), and fetch min(limit × 4, 400) rows.
  4. Gather for each row: every quote on every incoming funds edge (strongest first), the funders, and the documents.
  5. Merge rows with the same amount and period that are the same measure. Either the names match, or they share a document and there's evidence they're one measure:
    • an identical quote
    • one name's distinctive words contained in the other's
    • a quote that states the figure and names the other row
    The label comes from the best row (program over policy over funding, then the row with evidence). The other names become aliases. Evidence, funders and documents come from every row.
  6. Choose the evidence: the first quote that states the amount, otherwise the strongest edge's first quote. Then compute the flag and slice to limit.

Returns

{
  allocations: BudgetAllocation[];
  period: string | null;   // echoes the input
  basis: 'Individual figures extracted from source
          documents. Not summed. Totals, revenue and
          accounting lines are excluded.';
}

Gotchas

  • Negative amounts (savings) are kept and sort last.
  • Merging can return fewer rows than limit.
  • Show basis in the UI, so the list isn't read as a complete or additive account of the budget.
  • Merging is deliberately conservative. When it's unsure, it leaves two bars rather than hiding a measure inside another. A regression check keeps the two different $500m Fast-Track funds apart.

budget.funders querygraph:read

Input · object required

FieldTypeDefault
periodstring ≤ 40all periods
limitint 1–5012

What it does

  • Walks funds edges into measures.
  • Groups by funder entity and counts distinct measure names.
  • Keeps the top limit funders, each with the single largest measure it funds. Ties sort by name.

It reports counts, not totals: a count can be checked against the graph, whereas a sum would double-count roll-ups and re-extractions.

Returns

{
  funders: Array<{
    name: string;
    type: string;          // funder's entity type
    measureCount: number;  // distinct measure names
    largestMeasure: { name: string; amountAud: number } | null;
  }>;
  basis: 'Measure counts from `funds` edges.
          Amounts are single figures, never totals.';
}

Gotchas

  • A measure extracted under two names counts twice here. Counting doesn't merge the way allocations does.
  • Funder names are as extracted, so an occasional artefact appears, such as "SA State Budget 2026-27" typed as an event.

Why it exists

The quote is attached to the funds edge. It proves "X funds Y", but the amount may have been read from somewhere else in the chunk. For example, AUKUS carries $30bn, and its quote contains no figure.

UI contract

  • true → "Source sentence: states this figure"
  • false → "Relationship evidence: does not state the figure"

How it matches

  1. Strip dates and financial years first ("Dec 2031", "2026-27", bare years). They're never amounts, and in tables they weld onto the figure that follows them.
  2. Words with a magnitude ("$8.6 billion", "$53m") are already scaled and are compared as-is.
  3. Comma-grouped numbers are read whole, never as their fragments, and tried at ×1, ×1,000 and ×1,000,000. Tables are in $000 or $m, and Commonwealth tables put $ on cells too.
  4. Space-grouped table rows are read as runs of 2–4 adjacent column groups, so "Dec 2027 365 361 164 400" yields 365,361 ($000).
  5. Remaining bare whole numbers of 100 or more are scaled. Smaller numbers and decimals are counts or programme numbers and are compared as-is.
  6. Any candidate within 1% of |amount| counts as a match.

It checks digits, not units. An unconverted $000 cell still matches; see below.

Known limits

What the router can't fix on its own. Each of these needs a change in extraction or in the graph loader. They're recorded in docs/CAREERCRAFT-INTEGRATION.md §9.6.
  • The totals rule only reads names. It misses portfolio lines without "Total" ("Health Services", $5.6bn) and bundles ("…Fuel Resilience Package", $14.8bn, whose components are also listed). "Package" isn't in the rule because most packages are real initiatives. The fix is for the extractor to tag each figure as measure, total, revenue or balance.
  • Site-level repeats. "Warradale Barracks Housing Development" carries the Housing Fast-Track Fund's $500m and shows as its own bar. The merge leaves it, rather than risk hiding a measure.
  • Units. The flag can't tell whether a $000 cell was converted.
  • Mixed extractions. Each entity is one (type, name) whose attributes are merged key by key, so amount, period and source can come from different documents. For example, AUKUS shows $30bn, labelled "state". The fix is to store each extraction's amount, period and document as one record.
